# Request body schemas

Application web routes use `RejectUnknownRequestFields` to reject unknown top-level keys, uploaded files, and nested values before controller validation. Controller validation remains responsible for required fields, formats, lengths, and allowed values. Laravel's `_token` and `_method` form fields are accepted as transport metadata.

The remaining application routes have an empty body schema: `GET /`, `GET /about-us`, `GET /attorneys`, `GET /practice-areas`, `GET /the-firm`, `GET /legal-insights`, `GET /client-portal`, `GET /contact`, `GET /book-consultation`, `GET /book-consultation/new`, `GET /login`, `GET /client/login`, `GET /client/register`, `GET /client/recovery-codes`, `GET /attorney/login`, `GET /attorney-portal`, `GET /forgot-password`, `GET /admin/login`, and `GET /admin`. Laravel's built-in local storage serve/upload routes are disabled in `config/filesystems.php`; this application currently has no file-upload workflow. The `/up` health route also accepts no application body.

## Manual consultation payment operations

Payment is collected outside the site through firm-provided GCash or bank instructions; the client only reports that they sent it. An administrator must check the account and enter the verified transaction reference before the app creates a case and confirms the consultation. No card, GCash, or bank credentials are collected by the site. The firm supplies its own cancellation/refund terms and unpaid-request expiry for each proposal. Laravel's scheduled `consultation-payments:expire` task expires unpaid proposals every minute; hosting should invoke `php artisan schedule:run` once per minute. Client and admin page requests also expire overdue unpaid proposals as a fallback.

## Fields clients must never set

No public route accepts `user_id`, `userId`, `owner_id`, `is_admin`, `id`, `created_at`, or `updated_at`. The schema middleware rejects them on request bodies. Never add these to public form schemas. Laravel's session `user_id` is framework-managed and is not a request-body field.

Public contact and consultation forms also must not set `status`, `type`, `attorney_id`, or generated case fields such as `reference_no`, `accepted_at`, `timeline`, `resolved_at`, `outcome`, and `testimony`. These are assigned/managed server-side. The client portal lookup intentionally accepts `reference_no` only as a lookup credential, not as a value that creates or changes a case. Admin-only schemas allow the explicitly listed operational fields; admin authorization is enforced by the route middleware.
